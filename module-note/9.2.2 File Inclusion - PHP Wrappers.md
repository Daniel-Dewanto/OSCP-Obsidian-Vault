# PHP Wrappers
#cues

| CUES & QUESTIONS                                        | NOTES                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What are PHP wrappers?                                  | **Main Concept**: Built-in protocol handlers that extend PHP's capabilities (e.g. representing and accessing local or remote filesystems).                                                                                                                                                                                                                    |
|                                                        | In an attack context we abuse them to **bypass filters** or **obtain code execution** through File Inclusion (LFI/RFI) vulnerabilities in PHP web apps.                                                                                                                                                                                                       |
|                                                        | Many wrappers exist; we focus on two: `php://filter` and `data://`.                                                                                                                                                                                                                                                                                          |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| What does the `php://filter` wrapper do?               | Displays the contents of files **with or without** encodings like ROT13 or Base64.                                                                                                                                                                                                                                                                           |
|                                                        | Key use: read the **source** of executable files (e.g. `.php`) instead of executing them — lets us review app logic and hunt for secrets.                                                                                                                                                                                                                     |
|                                                        | Required parameter is `resource=`, which specifies the file stream to filter. Accepts **absolute or relative** paths.                                                                                                                                                                                                                                        |
|                                                        | Refer to example: [[9.2.2.1 Example of PHP Wrappers#php filter — reading admin.php]]                                                                                                                                                                                                                                                                          |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| Why do we need base64 encoding with `php://filter`?    | Without an encoder, PHP is executed **server-side** and never appears in the response — we only see rendered HTML, not source. A tell-tale sign is missing / unclosed tags (e.g. `<body>` never closed) where PHP was meant to run.                                                                                                                            |
|                                                        | Adding `convert.base64-encode` converts the resource to base64 **before** it is returned, so the raw PHP source travels back intact.                                                                                                                                                                                                                          |
|                                                        | We then decode locally: `echo "<b64>" \| base64 -d`.                                                                                                                                                                                                                                                                                                         |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| What can `php://filter` realistically get us?          | **Source disclosure** → frequently leaks hardcoded credentials, DB connection strings, and API keys.                                                                                                                                                                                                                                                         |
|                                                        | In the lab, decoding `admin.php` revealed MySQL connection details (username + password). Those creds can then be reused against the DB directly, or sprayed at other services such as SSH.                                                                                                                                                                    |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| What does the `data://` wrapper do?                    | Embeds data elements (plaintext or base64) directly into the running app's code, allowing **code execution** — not just reading.                                                                                                                                                                                                                             |
|                                                        | Useful **alternative** when we cannot poison a local file with PHP (no log poisoning / upload path available).                                                                                                                                                                                                                                               |
|                                                        | Refer to example: [[9.2.2.1 Example of PHP Wrappers#data — code execution]]                                                                                                                                                                                                                                                                                   |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| How is `data://` used for RCE?                         | Plaintext form: `data://text/plain,<?php ... ?>` with the PHP snippet **URL-encoded**.                                                                                                                                                                                                                                                                       |
|                                                        | Filter-evasion form: `data://text/plain;base64,<b64 snippet>` — base64 hides strings like `system` from WAFs/filters. Pair it with a `&cmd=` GET param for a reusable command shell (`<?php echo system($_GET["cmd"]);?>`).                                                                                                                                    |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| What is the key requirement / limitation of `data://`? | >[!warning] `data://` does **not** work on a default PHP install. The `allow_url_include` setting must be **enabled** in `php.ini` for it to function. (`php://filter` does **not** need this.)                                                                                                                                                                |
|                                                        |                                                                                                                                                                                                                                                                                                                                                             |
| `php://filter` vs `data://` — quick distinction?       | `php://filter` = **READ** source / disclosure → no special config needed.<br>`data://` = **EXECUTE** code / RCE → needs `allow_url_include = On`.                                                                                                                                                                                                             |

# Summary

PHP wrappers are built-in protocol handlers we can abuse through File Inclusion vulnerabilities. The `php://filter` wrapper lets us read the source of PHP files rather than executing them — using `convert.base64-encode` so the code returns intact for us to decode and mine for secrets like database credentials. The `data://` wrapper goes a step further and lets us embed and execute our own PHP, giving code execution when we can't poison a local file, either as a URL-encoded snippet or a base64 payload to dodge basic filters. The critical caveat is that `data://` only works when `allow_url_include` is enabled, whereas `php://filter` works out of the box.

---

# Key Takeaways
- `php://filter` reads source (disclosure); `data://` executes code (RCE).
- Use `convert.base64-encode` to exfiltrate PHP source without it running server-side; decode with `base64 -d`.
- Source disclosure via `php://filter` is a reliable way to harvest hardcoded creds (DB, API keys).
- `data://` base64 payloads help bypass filters that block strings like `system`.
- `data://` requires `allow_url_include = On` — it fails silently on default PHP.
