# File Upload — Executable Files (RCE)
#cues

| CUES & QUESTIONS                                      | NOTES                                                                                                                                                                                                                                     |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| How do we locate file upload mechanisms?              | **Main Concept**: Make educated guesses from the app's purpose. CMS → avatar upload, blog/page attachments. Company site → career section (CVs), or business-specific (e.g. lawyer's office → case files).                                |
|                                                       | >[!tip] Uploads are not always obvious to users — never skip enumeration when working a web app.                                                                                                                                          |
|                                                       |                                                                                                                                                                                                                                           |
| What's the goal of abusing an upload?                 | Upload a **web shell** to achieve code execution, then pivot to a **reverse shell**.                                                                                                                                                      |
|                                                       |                                                                                                                                                                                                                                           |
| First step once an upload form is found?              | Upload a benign file (`test.txt`) to confirm the mechanism works and isn't restricted to images only. Then try the actual webshell (`simple-backdoor.php`).                                                                               |
|                                                       | Refer to: [[9.3.1 Example of File Upload Vulnerabilities#Confirming the upload works]]                                                                                                                                                    |
|                                                       |                                                                                                                                                                                                                                           |
| PHP extension is blacklisted — how to bypass?         | Trial-and-error, since we can't see the filter's implementation. Two reliable tricks:                                                                                                                                                     |
|                                                       | **1. Alternative extensions** — `.phps`, `.php7`, `.phtml`. Simple filters often only block the common `.php`/`.phtml`; older/compat extensions still get executed by modern PHP.                                                         |
|                                                       | **2. Case variation** — rename `.php` → `.pHP`. Blacklists frequently compare against a **lowercase-only** string list, so mixed case slips through.                                                                                      |
|                                                       |                                                                                                                                                                                                                                           |
| How to confirm RCE after a successful upload?         | Note the upload path (often `uploads/`), then hit the shell with a command: `curl http://TARGET/.../uploads/simple-backdoor.pHP?cmd=dir`. `dir` output confirms command execution on the host.                                            |
|                                                       | Refer to: [[9.3.1 Example of File Upload Vulnerabilities#Confirm code execution]]                                                                                                                                                         |
|                                                       |                                                                                                                                                                                                                                           |
| How do we upgrade the webshell to a reverse shell?    | 1. Start listener **first**: `nc -nvlp 4444`.<br>2. Encode a PowerShell reverse-shell one-liner to base64.<br>3. Deliver via the webshell: `?cmd=powershell -enc <b64>` (URL-encode the spaces as `%20`).                                 |
|                                                       | >[!warning] `$ip` in the payload must be your **`tun0`** VPN IP (192.168.45.202), **not** a LAN address. Start the listener before triggering the callback.                                                                               |
|                                                       | Refer to: [[9.3.1 Example of File Upload Vulnerabilities#Reverse shell via PowerShell -enc]]                                                                                                                                              |
|                                                       |                                                                                                                                                                                                                                           |
| Why base64-encode the one-liner (and which encoding)? | The one-liner contains many special characters that break in a URL/shell. `powershell -enc` expects **base64 of UTF-16LE (Unicode)** — that's why we use `[System.Text.Encoding]::Unicode.GetBytes()` before `ToBase64String()`.          |
|                                                       |                                                                                                                                                                                                                                           |
| What privileges did the shell land with, and why?     | `whoami` → `nt authority\system`. The app was running under **XAMPP on Windows**, whose service ran as SYSTEM — so the shell inherits full privileges.                                                                                    |
|                                                       |                                                                                                                                                                                                                                           |
| Where are ready-made web shells on Kali?              | `/usr/share/webshells/` — subfolders for `asp`, `aspx`, `cfm`, `jsp`, `perl`, `php`, plus `laudanum`. Process is near-identical across languages; identify the target's framework, upload, place somewhere reachable, then send commands. |
|                                                       |                                                                                                                                                                                                                                           |
| Alternative bypass if extension filtering is strict?  | If the app lets users **rename/modify** files after upload: upload as an innocent `.txt`, then rename it back to the executable extension.                                                                                                |

# File Upload — Non-Executable Files (Traversal)
#cues

| CUES & QUESTIONS                                            | NOTES                                                                                                                                                                                                                              |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Can an upload still be dangerous if files can't execute?   | **Yes** — chain it with another vulnerability, most commonly **Directory Traversal**, to write files where they cause impact.                                                                                                       |
|                                                            | Example of a "useless" upload on its own: **Google Drive** — you can upload anything but never leverage it for system access.                                                                                                       |
|                                                            |                                                                                                                                                                                                                                  |
| What enumeration should we do on any upload form?          | Upload the **same file twice**: "already exists" message → you can brute-force server contents; an error message → may leak the language/tech stack. Also test whether a **relative path** in the `filename` is honoured.           |
|                                                            |                                                                                                                                                                                                                                  |
| How do we test for traversal in the upload?                | In Burp Repeater, modify the `filename` param to `../../../../../../../test.txt` and send.                                                                                                                                          |
|                                                            | >[!warning] The response echoing back `../` does **not** prove it worked — the app may have sanitized internally. It's a **blind** write; assume success only when no other vector exists.                                          |
|                                                            |                                                                                                                                                                                                                                  |
| Why do web-server run-as accounts matter here?             | Determines what we can overwrite. **Linux** (Apache/Nginx) → `www-data`. **Windows IIS** → Network Service (passwordless, low-priv) or App Pool Identities (7.5+). Language-embedded servers are often carelessly run as **root/Administrator** — always check.                    |
|                                                            |                                                                                                                                                                                                                                  |
| What's the classic non-executable exploit?                 | Overwrite root's **`authorized_keys`** with a public key we control, then SSH in as root.                                                                                                                                          |
|                                                            | Steps:<br>1. `ssh-keygen` → keypair (`fileup` / `fileup.pub`).<br>2. `cat fileup.pub > authorized_keys`.<br>3. Upload with traversal filename `../../../../../../../root/.ssh/authorized_keys`.                                     |
|                                                            | Refer to: [[9.3.1 Example of File Upload Vulnerabilities#Overwrite authorized_keys → SSH as root]]                                                                                                                                 |
|                                                            |                                                                                                                                                                                                                                  |
| How do we connect after the overwrite?                     | `ssh -p 2222 -i fileup root@TARGET`. If a stale host key blocks you (reused hostname, new box): `rm ~/.ssh/known_hosts` first.                                                                                                      |
|                                                            |                                                                                                                                                                                                                                  |
| Caveats / real-world risk?                                 | Blindly overwriting files on a production box can cause **data loss or downtime**. Also, root frequently lacks SSH access — but with no way to read `/etc/passwd` to find other users, it's often the only shot.                    |

---

# Summary

File upload flaws split into two cases. When the uploaded file can be executed, we upload a web shell — bypassing extension blacklists with tricks like alternative extensions (`.php7`, `.phtml`) or case variation (`.pHP`) — confirm RCE with a `?cmd=` request, then upgrade to a reverse shell using a base64-encoded PowerShell one-liner via `powershell -enc`. When the file can't be executed, the upload is only useful when chained with another bug: Directory Traversal in the `filename` parameter lets us write outside the web root, and the canonical payoff is overwriting root's `authorized_keys` to gain SSH access. Throughout, the server's run-as account governs what damage is possible, and blind writes carry real production risk.

---

# Key Takeaways
- Always upload a benign `.txt` first to fingerprint the filter before burning your webshell.
- Blacklist bypasses: alternative PHP extensions and mixed-case (`.pHP`) beat naive lowercase filters.
- Start the `nc` listener **before** triggering the callback; point the payload at `tun0`, not the LAN.
- `powershell -enc` needs base64 of **UTF-16LE (Unicode)** — hence `[Encoding]::Unicode.GetBytes()`.
- Non-executable uploads still kill via chaining: traversal in `filename` → overwrite `authorized_keys` → SSH as root.
- Traversal writes are usually **blind**; a reflected `../` in the response proves nothing.
- Kali ships webshells at `/usr/share/webshells/` (asp, aspx, cfm, jsp, perl, php, laudanum).
